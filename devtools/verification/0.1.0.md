# Local verification — 0.1.0

Verified 2026-09-20 on Minecraft 1.21.1, NeoForge 21.1.248 and Java 21.
This is local development evidence, not a release or deployment record.

## Executed gates

| Gate | Result | Scope |
|---|---|---|
| Plain JUnit | 6 passed, 0 skipped | Sheet geometry, coordinate boundaries, compass math, immutable provider values, visibility and lifecycle contract |
| Real-server GameTests | 12 passed | Actual cartography menus, ordinary and shift-click extraction, duplicate/capacity rejection, vanilla cloning/scaling/locking, persistence, private landmarks, real optional integrations, permissions, safe arrival and network validation |
| Real client booth | Complete | Actual cartography clicks, two bound sheets, terrain sync, two player heads, movement with travel view, registered atlas key, village selection/tracking, landmark editor and save packet, operator village teleport, unequip invalidation |
| Production jar | Built and inspected | Domain and production adapters present; test mod, fixtures and upstream integration jars absent |

Commands, from the repository:

```sh
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew test runGameTestServer jar --offline
bash devtools/booth.sh
JAVA_HOME=/usr/lib/jvm/java-21-openjdk-amd64 ./gradlew jar --offline
```

The final server run reported `All 12 required tests passed`; JUnit XML reported
six tests without failures or skips. The final client log reported every assertion
as `PASS`, followed by `atlas booth: COMPLETE`. Both Gradle invocations and the
final jar rebuild completed successfully. Gates were run individually, not claimed
as a separate clean-build run.

The real C.A.M.P. integration test deployed through its item, waited for ACTIVE,
teleported an operator into the camp, moved the operator outside, and folded it.
Its marker then disappeared. The Village Deed test used its actual claim/revoke
ledger. Permission tests used the server's real operator list. Network tests used
the real payload codec and server packet handler, covering stale sessions,
unmapped coordinates, unequipping, oversized data and defensive terrain copies.
The client walkthrough also covered the actual connection handshake.

## Rendered review

The booth ran muted at 1280×720, GUI scale 2, with Sodium 0.8.13-beta.2, Iris
1.8.14-beta.1 and Complementary Unbound 5.8.1 under software OpenGL. Only one
rendering client ran; it and its owned Xephyr window closed after completion.
Terrain was surveyed through vanilla map updates in the disposable fixture world.

framing, and a rapid-scroll click crash. The final screenshots are from the
subsequent passing walkthrough; they were visually inspected, not inferred from
test assertions. No external visual reference was supplied.

## Remaining review scope

Rusty's hands-on approval is pending. No live server, assembled pack, remote
multiplayer latency, large player population or broad resolution/shader matrix was
tested. Two players were exercised in one local server with one rendering client;
this does not establish behavior under WAN latency. Separate dimensions were
covered on the server, not by a client trip through every dimension. Optional-mod
compatibility is established for the jar identities above.

The atlas displays vanilla map terrain and provider markers; vanilla banner and
explorer-map decorations are not rendered in its custom view. Their original map
data is retained when sheets are recovered. There is no cave terrain or route
finding. These limits do not change the vanilla maps used as the terrain substrate.

No tags, pushes, GitHub releases, pack changes or live-server restarts were made.
