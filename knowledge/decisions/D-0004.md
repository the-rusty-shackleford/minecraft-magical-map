# D-0004 — Arrival loads a saved destination chunk, never generates one

Accepted 2026-09-22.

Rusty teleported to their own village from far away and was told "Destination terrain is
unavailable". `SafeArrival.loadDestination` asked the level for the chunk with
create=false, which answers only for chunks already in memory; its comment claimed it
"loads only an existing destination chunk", which it never did. Every destination beyond
the player's loaded radius was refused, which is most of what a teleport is for.

The rule stands: the atlas never generates terrain. The check now reads the chunk's saved
NBT from the region storage without loading it, accepts it only when its status is
`minecraft:full`, adds the vanilla post-teleport ticket so the chunk stays for the
arrival, and loads it. A chunk absent from disk, or saved before generation finished, is
still refused with the same message. Loading a saved chunk on the server thread costs a
disk read once per explicit teleport.

GameTests: a loaded chunk is available; a chunk generated 50,000 blocks away, saved, is
found on disk and loaded; a never-generated chunk is refused and remains ungenerated.
